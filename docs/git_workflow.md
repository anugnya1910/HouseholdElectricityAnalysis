# Version Control Workflow

The repository uses a simple, linear workflow suitable for an individual case study.

## Branching

* `main` holds the submitted, reproducible version of the project.
* Optional feature branches (for example `feature/dashboard`) are merged into `main` when complete.

## Commit message convention

Messages use the imperative mood and a short prefix:

| Prefix | Use |
|---|---|
| `data:` | Changes to data preparation or datasets |
| `analysis:` | New or revised analysis scripts |
| `model:` | Modelling changes |
| `dashboard:` | Changes to the Shiny application |
| `docs:` | Documentation and report changes |
| `fix:` | Corrections |

Example: `model: add generalized additive model to regression comparison`.

## Reproducibility rules

* Generated outputs in `outputs/` are committed so the results can be inspected without running R.
* Large binary model objects (`outputs/*.rds`) are excluded through `.gitignore` and regenerated by
  `run_all.R`.
* The random seed is fixed in `R/00_config.R`.
* The report is re-rendered after any change to the analysis scripts.
